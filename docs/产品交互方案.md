# Vibe Coding 产品交互方案

> 本文档描述 Vibe Coding 产品的页面结构、组件划分与核心交互，供产品讨论与后续组件化开发对齐。

---

## 一、产品定位与目标

- **产品名**：Vibe Coding（豆包 / 品牌可替换）
- **核心场景**：用户通过自然语言对话与 AI 协作，完成编程、原型设计、内容生成等任务；在「对话」与「预览/代码」之间无缝切换。
- **目标用户**：希望用对话式交互完成开发或原型的开发者/创作者。

---

## 二、整体信息架构

- **页面一（Chat 首页）**：唯一入口，承载所有对话。**无预览时**：左侧历史 + 右侧当前对话（欢迎语/消息列表 + 输入栏），不离开本页。
- **页面二（预览工作台）**：**仅当存在「应用生成」结果时**才进入，用于展示该对话对应的预览/代码；左侧为当前对话，右侧为预览与代码 Tab。

```
┌─────────────────────────────────────────────────────────────────┐
│  页面一：Chat 首页（入口）  / 或 /chat                            │
│  左侧：对话历史 │ 右侧：Chat 区域（欢迎语 / 当前对话 + 输入栏）   │
│  - 新对话、点快捷问题、点「无预览」的历史 → 均在本页展示对话     │
└─────────────────────────────────────────────────────────────────┘
                                    │
              仅当某对话有「应用生成」结果时，可进入页面二
                                    ▼
┌─────────────────────────────────────────────────────────────────┐
│  页面二：对话 + 预览（仅展示应用生成）  /workspace/:conversationId │
│  左侧：当前对话（消息列表 + 输入） │ 右侧：预览/代码（仅应用生成） │
└─────────────────────────────────────────────────────────────────┘
```

- **页面一**：所有对话的入口与主战场；无预览的对话全程在本页完成。
- **页面二**：仅用于「有应用生成结果的对话」，左侧对话、右侧预览/代码同屏查看。

---

## 三、页面一：Chat 首页

**参考**：第一张参考图（左侧历史 + 右侧大 Chat 区）

### 3.1 布局

| 区域     | 宽度（建议）               | 内容                                |
| -------- | -------------------------- | ----------------------------------- |
| 左侧边栏 | 固定或可收窄，如 260–320px | 品牌/Logo、新对话按钮、历史对话列表 |
| 右侧主区 | flex: 1                    | 欢迎语、快捷问题卡片、底部输入栏    |

### 3.2 左侧边栏

- **顶部**
  - 品牌名（如「豆包」） + 可选设置/用户头像。
- **新对话**
  - 主按钮：「新对话」+ 图标（编辑/加号），点击后清空右侧并聚焦输入框，**停留在页面一**。
- **历史对话**
  - 标题：「历史对话」。
  - 列表：每条展示图标 + 标题（首句或 AI 总结）+ 可选角标（未读/通知）。
  - **点击某条**：
    - **有预览（应用生成）**：进入**页面二**，加载该对话，右侧展示预览/代码。
    - **无预览**：**留在页面一**，右侧加载该对话的消息列表与输入，继续在本页聊天。
- **底部**
  - 可重复「新对话」或放置「设置/更多」等。

### 3.3 右侧 Chat 区域

- **欢迎区**
  - 主文案：如「有什么我能帮你的吗?」
- **快捷问题**
  - 若干可点击的卡片/按钮（资讯、趣味问答、笑话、设计小游戏、AI 概念等），点击后作为首条用户消息发送并**在页面一**进入对话。
- **底部输入栏**
  - 占位符：如「发消息或输入'/'选择技能」；左侧 @，右侧技能按钮、发送；发送按钮无内容时置灰。

### 3.4 交互要点

- **有预览才进页面二**：仅当对话存在「应用生成」结果时，才提供入口进入页面二（如历史项右侧按钮「查看预览」或点击该条后若检测到有预览则跳转）。
- 新对话、点击无预览的历史、点击快捷问题：**均在页面一**完成，右侧展示欢迎语或当前对话消息列表与输入。
- 技能通过状态区分，**不进路由**。

## 四、页面二：对话 + 预览工作台（仅展示应用生成）

**参考**：第二张参考图（左侧对话 + 右侧预览/代码）

**约定**：本页**仅用于展示已有「应用生成」结果的对话**，不承载无预览的会话。进入方式仅为：从页面一某条「有预览」的历史进入。

### 4.1 布局

| 区域 | 宽度（建议）               | 内容                                                            |
| ---- | -------------------------- | --------------------------------------------------------------- |
| 左侧 | 固定或可拖拽，如 360–420px | 当前对话：消息列表 + 输入栏 + 技能按钮                          |
| 右侧 | flex: 1                    | 预览/代码区：Tab（预览 / 代码）+ 主内容 + 可选「AI 生成」等操作 |

### 4.2 左侧对话区

- **顶部（可选）**
  - 当前对话标题、版本/分支（如 V2 下拉）。
- **消息列表**
  - 用户消息、AI 回复（含 Markdown、设计亮点列表、任务描述等）。
  - 可展示「任务已完成」等状态卡片（如「简单应用\_0301 V2」）。
  - 支持「使用 xxx 模板重新生成」等操作按钮。
- **底部**
  - 与页面一类似的输入栏 + 技能选择（编程等可高亮）。

### 4.3 右侧预览/代码区

- **Tab 栏**
  - **预览**：渲染结果（应用生成页/单页等）。
  - **代码**：当前项目或当前回复对应的代码（文件树 + 代码高亮）。
  - **多版本**：版本切换（如 V2）UI **先保留**，逻辑与粒度后续再定。
- **工具栏**
  - 主题切换、文件夹、分享、下载等。
- **主内容**
  - 预览 Tab：iframe 或内嵌预览组件。
  - 代码 Tab：文件列表 + 编辑器或只读代码展示。

### 4.4 交互要点

- 左侧消息与右侧预览/代码**联动**：切换对话或版本时，右侧内容随之更新。
- 从页面一进入时，通过 `conversationId` 加载**有预览**的对话，右侧默认展示预览或代码。
- **多版本**：UI 保留（如 V2 下拉），具体切换逻辑与 API 后续再定。

## 五、页面流转与路由建议

| 场景 | 路由建议 | 行为 |
|------|----------|------|
| 打开产品 | `/` 或 `/chat` | 页面一，左侧历史 + 右侧欢迎与输入 |
| 新对话 / 点快捷问题 / 点「无预览」历史 | `/chat`（或带 query 如 `?conversationId=xxx`） | **停留在页面一**，右侧展示当前对话（欢迎语或消息列表 + 输入） |
| 进入「有预览」的历史 | `/workspace/:conversationId` | **页面二**，加载该对话，右侧展示应用生成的预览/代码 |
| 仅分享预览（可选） | `/preview/:id` | 仅渲染右侧预览区（只读），无左侧对话 |

**技能**：不通过路由区分，仅前端状态。

## 六、组件化拆分建议

便于复用与维护，建议按以下层次拆分（与 spec 中 React + Tailwind + 函数组件一致）：

### 6.1 布局组件

- **AppLayout**：整体左右分栏。
- **SidebarLayout**：左侧边栏 + 右侧主区的通用布局，接收 `sidebar`、`main` 的 ReactNode。
- **WorkspaceLayout**：页面二专用，左侧对话 + 右侧预览区，可接收 content 与 tabs 配置。

### 6.2 页面一专用

- **ConversationHistorySidebar**：历史列表容器。
  - **ConversationHistoryItem**：单条历史（图标、标题、角标）。
- **ChatWelcome**：欢迎语 + 快捷问题列表。
  - **QuickQuestionCard**：单条快捷问题。
- **ChatInputBar**：底部输入栏（占位符、@、技能按钮、发送）。
  - **SkillButtonGroup**：技能按钮组，支持选中态。

### 6.3 页面二专用

- **ConversationPanel**：左侧对话面板。
  - **MessageList**：消息列表。
  - **MessageBubble**：单条消息（用户/AI、Markdown、操作按钮）。
  - **TaskCompletedCard**：任务完成等状态卡片。
- **PreviewCodePanel**：右侧预览/代码容器。
  - **PreviewCodeTabs**：预览 / 代码 Tab 切换。
  - **PreviewFrame**：iframe 或内嵌预览。
  - **CodeView**：代码展示（文件树 + 代码块）。

### 6.4 共享组件

- **Logo / Brand**：顶部品牌。
- **ButtonNewChat**：新对话按钮。
- **ChatInputBar**（与页面一复用）、**SkillButtonGroup**。

## 七、状态与数据（简要）

- **对话列表**：来自后端或本地缓存，需 id、title、updatedAt、可选 unread 等。
- **当前对话**：当前会话 id、消息数组、当前选中的技能、可选版本/分支。
- **预览/代码**：与当前对话或版本绑定，可由服务端根据 conversationId 返回预览 URL 与代码快照。

具体 store 设计（Zustand）与 API（SWR）可在技术方案中再细化。

---

## 八、已定结论

1. **页面一与页面二**：有预览（应用生成）才进入第二页；没有预览的对话全部在页面一展示。
2. **页面二用途**：仅用来展示应用生成（预览/代码），不承载无预览会话。
3. **技能与路由**：技能不进路由，仅用前端状态区分。
4. **移动端**：当前不考虑移动端适配。
5. **多版本/分支**：版本切换 UI（如 V2 下拉）先保留，逻辑与 API 后续再定。

---

## 九、验收要点（概要）

- **页面一**：左侧历史展示；新对话、快捷问题、无预览历史点击后均在页面一展示对话；有预览历史的入口可进入页面二。
- **页面二**：仅通过「有预览」的对话进入；左侧消息列表与输入、右侧预览/代码 Tab 切换、内容随对话联动；多版本 UI 保留。
- 路由：`/` 或 `/chat` 为页面一，`/workspace/:conversationId` 为页面二；技能不进路由。
- 组件按上述拆分，便于后续迭代与 Agent 协作开发。
- 当前不考虑移动端。
